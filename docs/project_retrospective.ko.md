# 프로젝트 전체 회고: 학습한 미래를 행동과 작업 완료로 연결하기

작성일: 2026-10-23 · 회고 v1 · 실험 근거 기준: 2026-10-22 / `322ae350186f7bb688cb07aaff89fd7521491f95`

이 문서는 문제를 선택한 이유, 진행 중 바뀐 판단, 주요 실험과 실패, 현재 한계를 연결한다. 새로운 실험 보고서나 성능 개선 선언이 아니다. 정식 비교와 그 이후의 개발 진단을 구분하며, 과거의 중단·실패·미실행을 현재 성공으로 바꾸지 않는다.

**프로젝트는 부품 밀기 정렬이라는 작은 로봇 과제에서 학습한 미래 예측을 행동 선택에 연결하고, 예측 정확도·후보 선택·실제 인계 준비 성공을 나누어 검증하는 실험으로 발전했다.** 구현과 정식 비교는 완료했지만, 다단계 학습의 작업 성능 개선과 최종 실패의 단일 원인은 확인하지 못했다. 후속 전체 후보 진단은 70/768회에서 자원 중단됐고 698회가 미실행이다.

## 1. 기술을 써보려던 관심이 검증 가능한 질문으로 바뀌었다

출발점은 기존 시계열 예측·비전 학습 경험에서 한 단계 나아가, 예측한 미래를 이용해 다음 행동을 고르는 과정을 이해하고 싶다는 관심이었다. VLA와 월드모델을 접했지만, 기술 이름이나 움직이는 데모만으로 프로젝트를 선택하고 싶지는 않았다.

초기 기획에서는 기술과 구현 내용이 먼저 구체화된 반면, 그 작업에서 예측 모델을 검토할 이유는 충분하지 않았다. 사용자는 “기존 방식의 부족함이 확인된 사실인가, 아직 가정인가”를 물으며 문제의 근거를 다시 확인하도록 했다. 이후 논의가 단순 제어의 충분성을 검증하는 쪽으로 기울자, 이번에는 학습 기술의 핵심을 직접 다루려던 목표가 빠지면 안 된다고 요구했다.

두 번의 수정에서 다음 원칙이 남았다.

1. **학습 동역학을 구현하고 행동 생성에 사용하는 것은 프로젝트의 선정 조건이다.**
2. **그 방법이 기존 방식보다 우수하거나 현업에서 필요한지는 검증 대상이다.**

기준선의 성공을 학습 기술을 제외하는 관문으로 삼지 않고, 학습 방법을 유리하게 만들기 위해 기준선을 약화하지 않기로 했다. 흥미·학습 가치·작업 가치·성능 우위를 같은 것으로 취급하지 않는 선택이었다.

이 초기 대화의 순서는 사용자가 제공한 기획 대화에 근거한다. 전체 대화나 개인의 과거 연구 자료는 공개 저장소에 첨부하지 않았다. 현재의 문제·방법·주장 범위는 [사업 보고서 §1](business_report.ko.md#1-판단-요약과-문제의-의미)과 [기술 보고서 §1](technical_report.ko.md#1-문제와-연구-질문)에 반영돼 있다.

## 2. ‘목표로 옮기기’를 ‘다음 작업에 넘길 준비 만들기’로 구체화했다

작업은 수평 작업대의 어긋난 단일 직사각형 부품을 옆에서 밀어 지정된 위치·방향에 맞추는 것이다. 잠재 사용자는 부품 공급·취급 셀의 정렬 방식을 비교하는 자동화 엔지니어로 설정했다. 실제 기업 의뢰나 고객 검증을 받은 프로젝트는 아니다.

기존 조사에서 일정한 자세로 부품을 공급하는 작업의 필요성과 기계식 대안을 확인했다. 해당 공개 사례가 지그·트랙·셔틀로 작업을 해결한다는 점도 함께 기록했다. 따라서 작업의 존재만으로 학습 모델의 필요성이나 별도 밀기 모듈의 수요를 정당화하지 않았다. 직접 집기, 전용 지그·피더, 기하 피드백, 단순 예측 계획도 비교해야 할 대안이었다.

프로젝트의 주된 성격은 **B2B 적용 맥락을 둔 학습·기술 검증**이다. 학습 동역학과 계획의 결합 자체를 새로운 알고리즘으로 주장하지 않는다. 실무적 의미는 제어 방식을 판단할 근거를 만드는 데 있고, 비용 절감·택트타임·수율·ROI는 미검증 가정으로 남겼다. 관련 외부 자료와 적용 조건의 차이는 [사업 보고서](business_report.ko.md)에 정리돼 있다.

작업 성공은 목표 근처를 지나갔는지나 정지 화면의 모양으로 판단하지 않았다. 최종 인계 준비 계약은 다음과 같다.

| 항목 | 실험에서 정한 기준 |
|---|---|
| 위치 오차 | 5mm 이하 |
| 방향 오차 | 직사각형의 180° 대칭을 고려해 3° 이하 |
| 부품 선속도·각속도 | 0.01m/s·0.05rad/s 이하 |
| 연속 유지 | 위 조건을 0.3초 유지 |
| 작업 제한 | 최대30초, 자동 재시도0회 |

이는 산업 표준 공차가 아니라 실험 명세다. 실제 후속 집기·삽입은 수행하지 않았다. 개발 중 보완한 0.5초 연속 영 명령 자료와 최종 성공 기준인 0.3초 유지는 서로 다른 목적의 값이다.

## 3. 범위를 줄이되 학습·예측·행동의 연결은 남겼다

M1·M4와 추가 예산10만원 미만이라는 기획 조건에서, 영상·언어·로봇팔 전체를 동시에 다루지 않고 상태 기반 MuJoCo 평면 밀기를 선택했다. 예산은 기획 제약이며 실제 지출액을 이 회고에서 산정한 것은 아니다. 현재 구현은 작은 행동 조건부 동역학 모델이다. 영상 잠재 월드모델, VLA, 강화학습 정책은 구현 범위에 포함하지 않았다.

| 경계 | 실제 구현과 책임 |
|---|---|
| 현재 관측 | 부품의 XY·yaw·속도6개와 푸셔의 XY·속도4개, 총10차원 |
| 행동 | world XY 목표 속도2개, 정상 행동 구간0.1초. 요청·적용 명령과 실제 속도를 구분 |
| 학습 입력 | 상대 XY·방향 표현·속도·적용 명령의11차원 특징 |
| 학습 출력 | 다음0.1초의 전체 상태 증분10개. 푸셔의 미래도 예측 |
| 계획 | 128후보를5단계·0.5초까지 예측해 비용·유효성 평가. 첫0.1초만 실행 |
| 기존 구성 | 속도 추종·접촉 적분은 기존 제어기와 물리 엔진, 영 명령과 유지 판정은 공통 감독기 |

다단계 자유 예측은 `실제 현재 상태 → 예측 상태1 → 예측 상태2 → … → 예측 상태5`처럼 예측한 전체 상태를 다시 입력하는 과정이다. MLP는11→128→128→10 구조다. 목표 자세는 동역학 입력 대신 계획 비용과 작업 판정에 사용한다.

계획 중 미래 물리 조회0회는 예측을 하지 않았다는 뜻이 아니다. 모델이 실제 미래 정답을 몰래 조회하지 않았다는 검사다. 후보별 실제 미래는 별도의 오프라인 진단에서만 실행했다. [입출력·계획·학습의 정확한 계약](technical_report.ko.md#3-시스템과-입출력-계약)을 따른다.

처음 보는 독자를 위해 이후 방법 이름을 고정해 설명한다. **G**는 조정한 기하 피드백, **R**은 선형 동역학과 공통 계획기, **S1**은 한 단계 학습 MLP와 공통 계획기, **SK**는 같은 MLP에 다단계 자유 예측 손실을 추가한 방법이다. `11·23·47` 접미사는 학습 seed다. R은 Ridge 후보 중α=0이 선정된 최종 선형 모델이며, 모든 기존 물리·학습 방법을 대표하지 않는다.

## 4. 개발은 연결 확인에서 실패 가설의 통제 비교로 진행됐다

### 4.1 처음의 P0–P5 계획과 실제 판단

| 단계 | 주요 작업 | 진행 중 중요해진 선택 |
|---|---|---|
| P0 | 문제·범위·기록 계약 | 작업·학습·사업 효과를 분리하고 미정값을 등록 |
| P1 | 물리·좌표·시간·상태 복원 | 잘못된 물리나 시간 정렬을 학습 문제로 오인하지 않기 |
| P2 | 작은 데이터·MLP·계획·실행 연결 | 실행 구조가 작동해도 작업 성공으로 승격하지 않기 |
| P3 | 조정한 기준선·본 자료·공통 모델 | 기준선과 데이터 생성 경로도 수치 대조 후 채택 |
| P4 | S1/SK 분기·후보 비용·실패 진단 | 바꾼 요인과 비교 조건을 명시하고 개선되지 않은 결과 보존 |
| P5 | 설정 동결·정식 비교·재현·보고 | 성능이 불리해도 유효한 비교와 원본을 유지 |

초기 물리 검사는 한 번에 통과하지 않았다. 시간 간격을 바꿨을 때 반응이 달라지는 조건들을 확인하고 접촉 설정 등을 수정해 재검사했다. 본 자료 수집 전에도 긴 G 실행의 수치 대조가 맞지 않아 수집을 보류했다. G의 접근·후퇴·전환과 속도를 조정한 뒤 채택했다. 더 느려진 기준선도 작업 기능과 수치 대조를 만족한다는 이유로 남겼다. 이 검사는 선언한 시뮬레이션 범위의 검증이며 현실 물리의 정확성 증명은 아니다.

작은 학습·계획 연결 뒤에는 시간 초과와 작업영역 이탈이 남았다. 개발 실행의 종료 위치 오차5.542mm도5mm 기준 밖 실패로 유지했다. ‘검사 통과’, ‘정렬 성공’, ‘사용자가 이해함’이 서로 다른 판정이라는 점을 문서와 진행 기준에 반영했다.

P3의 본 자료는90개 family·4,800전이였고, 학습60·검증30family로 분리했다. 정규화는 학습 자료로만 계산했다. 연속 프레임의 임의 분할을 피했지만 이것만으로 과적합과 일반화 문제가 모두 해결된 것은 아니다. 초기 상세 개발 기록 전부가 공개 묶음에 포함된 것은 아니며, 이 경과는 보존된 로컬 단계 보고서와 현재 [기술 보고서 §8](technical_report.ko.md#8-개발-과정에서-실제로-좁힌-설명)을 함께 대조해 정리했다.

### 4.2 학습 목적의 차이를 비교하기 위한 공통 출발점

S1과 SK를 서로 다른 초기화·학습량의 모델로 비교하지 않도록 seed별 공통 가중치·Adam 상태·RNG·정규화·자료·배치 순서에서 분기했다. 각각1,000회 추가 갱신하고, validation으로 선정한 SK의 가중치는0.1이었다.

`S1: 한 단계 손실` / `SK: 한 단계 손실 + 0.1×5단계 자유 예측 손실`을 비교했다. 동일 갱신 수는 연산량·시간·수렴 정도의 동일성을 뜻하지 않는다. 추가 항이 Adam 경로에 주는 효과까지 별도로 분리한 최종 비교도 아니다. [학습 계약과 제한](technical_report.ko.md#4-비교-방법과-학습-개입)을 따른다.

| 상대 위치를 직접 학습하면 좋은가? | 같은 D11 자료·구조·예산에서 상대XY 손실항만 추가한 R1을 비교 | 일부 접촉 오차가 줄어도 정지 상대XY 오차는0.614→1.193mm로 악화 |

후보77은 예측상 준비되는 행동이었지만 실제1초 동안 옆면 접촉 진입이 없고 부품이 정지했다. 실제 상태를 다시 넣은 첫 전이에도 오차가 있었다. 기존 train에 영 명령은 있었으나 긴 연속 정지 창이 부족했다. 따라서 ‘정지 자료가 전혀 없다’, ‘재귀 오차 하나 때문’, ‘보조 손실을 넣으면 해결된다’ 같은 설명을 그대로 채택하지 않았다.

Adam 대조도 복사본의 국소 손실 변화다. 다른 배치에서 유래한 방향이 정지 조건을 악화하는 사례를 확인했지만, 학습 전체나 최종 실패를 하나의 optimizer 원인으로 입증하지 못했다.

**후기 D11 자료·R1 상대항·Adam 진단과 H10 비용은 최종 모델·비용으로 승격하지 않았다.** 최종 비교는 P4-02의 S1/SK update1000과 원래 H5 비용을 사용했다. [당시 원고7개와 출처](../artifacts/development/index.md)는 국소 개발 관찰이며 공개 준비에서 모두 새로 실험·재검산한 결과가 아니다. 같은 약자가 다른 개발 설정에 쓰인 경우도 있으므로 후기 자료 유지군R을 최종 선형 모델R과 혼동하지 않는다.

## 6. 리뷰가 진단의 빈틈을 드러냈고, 보완 실행은 자원 문제에 부딪혔다

### 6.1 형식·가독성 보완과 내용 주장의 수정

사업·기술 보고서는 Markdown 원본과 제출용 PDF로, 학술 원고는 IEEEtran 기반 LaTeX와 PDF로 정리했다. 핵심 근거는 PDF 본문에 두고 세부 자료는 저장소로 연결했다. 그림·표에 G/R/S1/SK와 분모를 설명하고 README를 문제·방법·결과·기여·한계 순서로 재구성했다. 외부 학회 심사 통과를 뜻하지 않는다.

내용 검토에서 E1이 마지막 정렬을 직접 검사하지 않았다는 점이 분명해졌다. E1은 G 경로의 초기 접근 상태와16후보를 사용했고 실제 후보 끝점도 목표에서 최소49.462mm 떨어져 있었다. 고정 예측·E1·E2는 상태 분포와 후보군도 달랐다. 따라서 세 결과를 나열한 것과 예측 개선이 끊긴 원인을 식별한 것을 구분해 설명을 수정했다. [리뷰어 관점 검토](reviewer_assessment.ko.md)는 내부 내용 검토이며 외부 전문가 자격이나 학회 심사 결과가 아니다.

### 6.2 같은 전체 상태·후보에서 예측과 실제 미래를 대조

후속 개발은 목표 근처·실패 직전 상태를 복원하는 데서 시작했다. 관측10개뿐 아니라 물리 내부 상태·시간·직전 명령·유지 이력·계획 문맥까지 고정했다. 원래 내부 snapshot이 없는 시점은 원시 전이·문맥·후보 해시 일치로 복원했고, 없던 원본 snapshot과 직접 비교했다고 주장하지 않았다.

| 기호 | 실제 의미 |
|---|---|
| F-O0 | 실패 직전 offset-00 / S1-23 / tick254 |
| N-T | 목표 근방 translation-03 / S1-11 / tick78 |
| A | 명목 명령을0.5초 고정하고 원래 H5 비용 평가. 미래 재계획·감독기 명령 치환 없음 |
| B | 현재 자세에 따른 영 명령과 추가 관찰시간을 포함해 최대0.8초 준비 여부 확인 |

두 상태×첫16후보 ID×A/B×3반복으로192개 반사실 궤적을 실행했다. 세 반복은 결정론적 재현 검사이며 독립 초기조건·잡음 표본이 아니다. F-O0의16개 ID는 실제로는10종 명령열이었다.

F-O0의 실제 A는 모두 물리 유효했지만 여섯 MLP는 그 후보들을 예측상 거절했다. 모델·유효성 경계의 국소적 거짓 거절 근거다. 해당 후보가 인계에도 유리했다거나 그 오류만 고치면 전체 작업이 성공한다는 뜻은 아니다. N-T 후보9는B의0.6초에서 준비됐지만 같은0.5초까지는A/B 모두 준비되지 않았다. 감독기·관찰 길이·종료 규약이 함께 달라 정지 규칙의 단독 효과로 분리하지 않았다. [복원·사전 실행 보고](followup_restore_and_pilot.ko.md)를 따른다.

### 6.3 실행기·검사기도 틀릴 수 있었다

전체 진단을 준비하며 모델·정규화 파일을24개라고 잘못 단정한 사전 검사가 중단됐다. 검토도 같은 전제를 놓쳤다. 실제 원래 목록은22개였고, 전체 경로→SHA 지도로 검사하도록 바꿨다. 첫 실패는 예측·새 물리 실행 전이었으며 당시 코드·기록을 보존했다. [정정 기록](../artifacts/validation/nt_preflight_binding_correction.v1.json)은 모델이나 결과의 변경이 아니라 검사 전제의 오류임을 구분한다.

여러 상태의 전체 진단은 예산을 넘어서 N-T 한 상태의128후보로 범위를 줄였다. 일곱 모델의 예측을 실제 미래보다 먼저 저장·봉인하고, 모델마다 물리를 중복 실행하지 않고 공통 실제 후보 결과와 대조하도록 했다. 예정 실제 실행은128×2×3=768건이었다.

진입 검사는 통과했지만 전체 결과 저장·복원 묶음의 관측 최대 비용이 증가해70/768회에서 자원 규칙으로 중단했다. 698회는 실패가 아니라 미실행이다. 완료70회의 raw와 검증은 보존했다. 전체128후보의 실제 순위·선택손실과 새 실제 전이의 teacher-forced 평가는 완료하지 못했다. [당시 실행·중단 보고](nt_fullbank_execution.ko.md)에 남긴다.

### 6.4 ‘저장이 느리다’는 설명도 분해해서 확인했다

기존 묶음 시간에는 파일 처리뿐 아니라 저장 함수 내부·읽기 함수 내부·트리 전후·객체 전후의 네 exact 비교가 포함돼 있었다. 원본과 검증 수준을 유지한6사례×3회 계측 및 원래 함수3회 대조에서21쌍의 NPZ/gzip 내용이 원래 사례와 같았다.

느린 후보11/B의 평균6.171초 중4.435초, **71.9%가 네 exact 비교**였다. 압축·쓰기·flush/fsync 등은 약0.106초였다. 같은8구간이라도 후보11/B에는 더 많은 접촉 기록과 중첩 진단이 있었다. 현재 재현에서는 자료 순회·검증 부담이 컸지만, 과거 실행 순간의 OS·발열·캐시 원인까지 식별한 것은 아니다.

새 관측 최대6.429초와 준비·사후 정리 비용까지 반영한 마지막 자원 예상은158.46분이었다. 실제로 그 시간을 썼다는 뜻은 아니다. 이는 **후속 진단의 누적2시간 예산**이며 프로젝트 전체 개발기간이나 비용이 아니다. 기존 최대값을 빠른 평균으로 낮추거나 검증을 생략해 통과시키지 않았다. [분리 측정과 잔여 예산](nt_storage_profile.ko.md)에 근거를 보존했다.

기여는 상태·행동·시간 계약, 학습과 계획의 연결, 통제 비교, 실패 가설의 대조, 원본과 결과를 추적하는 근거 묶음이다. 새 알고리즘·범용 월드모델·실물 성능·비용 절감은 현재의 기여로 주장하지 않는다.

사용자는 문제의 근거, 학습 목표, 성공 판정, 진행·보류 기준을 제시하고 선택했다. Codex는 코드 작성·학습·반복 실행·검산·시각화·문서화를 수행하고 지원했다. 모든 코드를 사용자가 직접 작성했다고 쓰지 않는다. 산출물의 존재만으로 개인의 독립적 설명·수정 역량을 평가하지 않으며, 입력·손실·비용·실패 가설을 설명하고 작은 조건 변경을 직접 검증하는 확인은 별도다.

다음 작은 개발 질문은 **동일한 타입·비트·전체 필드와 해시·직접 동등성 검사를 더 빠르게 수행할 수 있는가**다. 작은 저장 사례에서 동등성을 먼저 확인하고, 새 버전과 남은 전체 자원을 다시 가격화해야 한다. 실행 가능성이 확보되면 **목표 근처의 같은 후보에서 모델의 어떤 오판이 선택과 실제 인계에 영향을 주는가**로 돌아간다. 이 회고는 추가 실행이나 예산 변경을 승인하는 문서가 아니다.
