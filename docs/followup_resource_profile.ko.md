# 저장·재현 검증 시간 분리와 다음 진단의 자원 범위

2026-10-22 · 별도 실행 비용 측정 완료 · 원래 D3 전체는 미실행

후속 갱신: [N-T 전체128 사전 검사](nt_fullbank_preflight.ko.md)를 완료했다. 아래 약 72분은 당시의 계획값이다. 새 완전 결과 저장·복원과 원본 대조의 적용 범위를 실측·구분한 최신 조건부 계획은 누적 102.51분이며, 아래 측정 결과와 당시 산식은 그대로 보존한다.

## 1. 판단하려는 문제

[D1/D2](followup_restore_and_pilot.ko.md)는 전체 상태 복원과 작은 후보 실행의 정확성을 확인했다. 그러나 물리·저장·검증을 합친 최대 단가로 계산한 6상태 D3는 2시간 예산을 넘었다. 이번에는 **원본, 전체 raw, fsync, 인증 해시, 비트 단위 왕복 비교와 전체 실행 결과의 3회 재현 비교를 유지할 때 어떤 작업에 시간이 드는가**를 측정했다.

검증을 줄이거나 모델을 재학습하지 않았다. 원래 모델 7개·물리·후보·비용·인계 기준과 동결 결과를 보존했다. 측정 자료는 로컬 `runs/followup-resource-profile-20261022-01`에 별도로 저장했다. 기존 `runs/followup-near-goal-20261022-01`과 원래 정식 실행을 덮어쓰지 않았다.

## 2. 무엇을 어떻게 측정했는가

### 계산 측정: 같은 후보를 실제로 재실행

N-T/F-O0의 A/B별 첫 반복 raw 크기 최소·최대 후보와 N-T 후보9의 B를 합친 **9개 조합을 3회씩**, 총 27궤적·174구간 재실행했다. 후보 크기와 조건으로 표본을 고르고, 이번 처리 시간을 보고 표본을 바꾸지 않았다. 두 상태를 대표하는 무작위 표본이나 새로운 성공률 평가가 아니다.

- 변경하지 않은 `run_followup_probe`와 실제 물리 환경을 사용했다.
- 환경 생성·복원·snapshot·step 시간을 감쌌다. `env_step`은 엔진 연산뿐 아니라 환경 내부의 하위 상태·접촉 진단 생성도 포함한다.
- 모든 새 초기 snapshot/StepResult가 해당 원래 D2 raw와 정확히 일치했다. 각 조합의 전체 `FollowupProbe` 3반복 비교와 새 raw 저장·재읽기 비교도 통과했다.
- 원래 raw와 추가 대조하는 시간은 별도 측정하여 기존 실행 비용 추정에서 제외했다. 전체 실행 결과의 반복 비교와 저장 왕복 비교는 제외하지 않았다.

### 기록 측정: 저장 자료를 동일 codec으로 다시 기록

같은 9개 조합의 기존 3반복 자료를 인증한 뒤, 3회 측정했다. 27개의 새 raw 쌍은 **각각 원본 쌍과 파일 SHA까지 같았다**. 실제 codec과 비교 함수를 그대로 호출하면서 중첩 호출의 시간을 배타적으로 합산했다. 실제 재실행 측정을 먼저 끝낸 뒤 기록 측정을 시작하여 두 프로세스가 경쟁하지 않았다.

외부·내부 파일 해시, 스키마·dtype·shape 검사, 두 번의 fsync, 양쪽 typed SHA와 재귀적 직접 비교를 유지했다. 저장된 경계·진단 배열·판정의 반복 비교와 실행 중 전체 `FollowupProbe` 비교는 범위가 다르므로 별도 기록했다.

이 측정은 소스 인증 후의 파일 캐시와 저장 직후 재읽기 조건이다. 디스크 캐시를 비운 측정이나 전원 장애 복구 시험은 아니다. 프로파일러를 켠 별도 CPU 분석은 주요 시간 측정에 합치지 않았다.

## 3. 실측 결과: 시간이 어디에 들었는가

계산 측정에서 기존 D2 파이프라인에 대응하는 27건 합계는 **54.403초**다. 아래 비율은 그 합계에 대한 값이며 원래 192건 전체의 분해값으로 소급하지 않는다.

| 작업 | 27건 합계 | 비중 |
|---|---:|---:|
| 환경 step: 물리와 기존 하위 상태·접촉 기록 생성 | 3.322초 | 6.1% |
| 환경 생성·복원·snapshot | 1.348초 | 2.5% |
| 나머지 probe 검증·task·기하·비용 계산 | 1.364초 | 2.5% |
| raw 구성·압축·저장·fsync·쓰기 인증 | 6.362초 | 11.7% |
| raw 인증·재읽기·복원 | 1.341초 | 2.5% |
| 저장 왕복: 양쪽 typed SHA와 직접 재귀 비교 | 24.358초 | 44.8% |
| 전체 실행 결과의 반복 재현 비교 | 16.267초 | 29.9% |
| 경계 진단 저장·receipt 등 나머지 | 0.039초 | 0.1% |

**두 정확 비교가 약 74.7%**를 차지했다. 이 결과는 디스크 쓰기 자체가 주된 원인이라는 설명을 지지하지 않는다. 별도 기록 측정에서도 왕복 비교 24.196초 중 typed digest가 14.528초, 직접 비교가 9.667초였다. raw 구성 3.526초, 열 묶음 생성 1.182초, XZ 헤더·압축·쓰기 1.215초였고, fsync는 합계 약 0.018초였다. 중첩 단계를 중복 합산하지 않았다.

저장 자료 비교의 별도 CPU 분석에서는 Python의 재귀 순회·형식 검사·해시 프레이밍이 큰 비중을 차지했다. 따라서 다음 성능 개선 후보는 **동일한 해시 바이트열과 직접 비교를 유지하는 구현 최적화**다. 이번에는 비교기를 수정하거나 속도 개선을 입증하지 않았다.

계산 측정 전체는 79.805초, 기록 측정 전체는 87.897초였다. 여기에는 소스 읽기·추가 원본 비교·CPU 분석 등 벤치마크 자체의 작업도 포함한다. 이 전체 시간을 새 실행의 구간별 비용에 다시 곱하지 않고 이미 쓴 자원으로 별도 계상한다.

## 4. 2시간 예산을 다시 적용하는 방법

[자원 계산서](../artifacts/followup/20261022-resource-profile/resource_summary.json)에 기계적으로 재계산 가능한 산식을 남긴다.

- 새 계산의 기존 파이프라인 환산 최대 단가는 약 **0.463831초/구간**이다. 과거 D2 최대 **0.481161초/구간**보다 작지만, 표본·시간대 차이로 상한을 낙관적으로 낮추지 않는다. 둘 중 큰 값과 안전계수 1.5를 사용한다.
- D1/D2와 이번 두 측정의 실행 시간을 누적한다. 새로 2시간을 부여한 것으로 예산을 초기화하지 않는다.
- 상태당 복원 입력 인증·모델 7개 추론·teacher-forced 평가·집계·보고를 위한 120초 여유를 별도로 둔다. 이는 실측 보장값이 아닌 계획 여유다. 실행기의 사전 검사에서 실제 고정 비용을 확인해야 한다.
- 새로운 상태를 포함하는 6상태 범위에는 남은 원래 경로 복원 685구간을 포함한다. N-O tick246은 이미 F-O0 복원 중 확보했다.
- 전체 raw와 새 측정 raw를 보존하며, 저장 5GiB 상한과 디스크 여유 2GiB를 유지한다. D2 결과 재사용·모델 축소·반복 축소·후보 축소·추가 bank는 기본 계산에 넣지 않는다.

| 다음 실행 범위 | 실제 궤적 수 | 새 미래 구간 상한 | 이미 쓴 시간 포함 계획값 | 판정 |
|---|---:|---:|---:|---|
| N-T 한 상태, 원래 128후보 전부, A/B 각 3반복 | 768 | 4,992 | 71.88분 | 실행기 사전 검사 대상으로 권고 |
| N-T와 F-O0 두 상태, 같은 전체 조건 | 1,536 | 9,984 | 133.93분 | 누적 2시간 초과로 보류 |
| 원래 D3의 6상태 전체 | 4,608 | 29,952 | 6.43시간 | 누적 2시간 초과로 보류 |

이미 쓴 실행 시간은 589.82초(9.83분)다. N-T 범위의 추가 계획 시간은 62.05분, 누적 저장량은 약 0.699GiB로 계산됐다. 저장 단가는 이번의 전체 측정 trial 폴더에서 관측한 최대 89,074.4B/구간을 사용해 기존 88,934.8B보다 보수적으로 잡았다. 정확한 누적 시간·저장량은 자원 계산서에 남겼다. 위 시간은 관측한 단가에 안전계수를 적용한 계획값이며, 모든 향후 후보의 실행 시간이 그 이하라는 수학적 보장은 아니다. 사전 검사와 실행 중 시간·공간 검사가 필요하다.

## 5. 왜 다음은 N-T 전체 128후보인가

모델 7개, A/B 규약, 3회 재현, 원본 보존과 정확 비교를 유지하고 **상태 수를 한 개로 제한**하는 것이 현재의 적절한 축소다. 새 범위는 원래 D3 전체 완료와 구분해야 한다. 아직 본 진단을 실행한 것은 아니다.

N-T의 기존 첫 16후보에서는 A의 ready가 없었고 B 후보9가 0.6초에서 ready였다. 전체 128개를 평가하면 같은 0.5초 A 조건에서 stable ready 후보가 존재하는지, 예측 유효성과 비용 순위가 실제 결과를 어떻게 다루는지 확인할 수 있다. 이미 국소적 거짓 거절을 확인한 F-O0보다 **아직 식별하지 못한 비용–인계 질문**에 답할 여지가 있다. ready_A가 끝내 없으면 비용 가설은 계속 미분리로 남긴다.

한 상태 128개를 끝내도 추가 bank를 검사하지 않으면 후보 탐색 부족을 확정할 수 없다. 한 S1 실패 경로의 사후 선택 상태이므로 S1/SK 일반 우열이나 원래 E2 실패 전체의 원인으로 확대하지 않는다. D2의 16후보를 본 실행 결과로 재사용하려면 v1의 드라이버·설계·입력·bank 동일성 규칙을 별도로 충족해야 하므로, 이번 권고 예산은 재사용 없이 계산했다.

다음 작은 행동은 **새 부분 진단 규격과 실행기에서 입력·128후보·모델 결합 및 실제 고정 비용을 확인하는 사전 검사**다. 통과 후 전체 128후보를 실행하고, 시간 상한에 걸리면 원시 prefix와 완료·미실행 분모를 보존한 채 중단하도록 해야 한다. 기존 결과를 이번 비용 측정으로 교체하지 않는다.
