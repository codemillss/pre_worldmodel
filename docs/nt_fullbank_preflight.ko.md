# N-T 전체 128후보 실행기 사전 검사

2026-10-22 · 사전 검사 통과 · **아래는 본 실행 전 기록**

후속 상태: [전체 실행은 진입 후 70/768회에서 자원 중단](nt_fullbank_execution.ko.md)했습니다. 이 문서의 102.51분은 최종 정리 여유 120초를 둔 당시 계획이며, 본 실행은 이를 600초로 늘려 진입한 별도 고정 설정입니다. 아래 수치를 최종 완료 결과로 읽지 않습니다.

## 1. 이번에 확인한 것

[기록·재현 비용 측정](followup_resource_profile.ko.md) 이후, N-T 한 상태의 전체 128후보를 평가하기 전에 입력·후보·7모델의 결합과 실제 고정 비용을 확인했다. 전체 후보의 예측은 실제 미래 실행보다 먼저 저장했다. 실제 사전 실행은 미리 지정한 후보 **0·9·127 × A/B × 3반복 = 18궤적**으로 제한했다.

원래 정식 실행, D1/D2, 시간 측정, 모델·정규화·물리·9항 비용·인계 기준을 보존했다. 실제 동작은 변경하지 않은 `run_followup_probe`를 사용했다. 첫 반복의 전체 결과 필드를 추가로 저장·복원해 독립 검토할 수 있게 했으며, 이 추가 비용을 예산에 포함했다.

**판정:** 사전 검사와 원본 보존·재현 검증은 통과했다. 다음 전체 실행은 작업별 적용 범위를 정확히 지키는 실행기를 전제로 누적 **102.51분·약 0.963GiB**로 계획할 수 있다. 현재 진입점은 사전 검사 전용이며, 전체 실행을 자동 시작하지 않는다.

## 2. 입력·후보·모델의 동일성

| 항목 | 확인한 내용 | 결과 |
|---|---|---|
| N-T 출처 | translation-03 / S1-11 / tick78 | D1 출처·원본 해시 일치 |
| 전체 입력 | 물리 integration 상태·RNG·환경 보조 상태·관측·task 시계/유지 이력·직전 명령·planner/G 문맥·설정 | typed SHA `f1c8a69a…dbd7f3` 일치, 저장·재읽기 exact |
| 후보 | 원래 RNG `[6811,3,78,0]`, warm sequence와 현재 기하 문맥으로 재생성한 float64 `[128,5,2]` | 값·순서·출처 라벨 exact, SHA `eee0b75a…3f2db` 일치 |
| 후보 중복 | 원래 ID와 순서를 유지 | 128개 명령열 모두 서로 다름 |
| 모델 | R, S1-11/23/47, SK-11/23/47 | 7모델·정규화의 실제 **22파일** 전체 경로→SHA가 원래 D2·공개 출처·동결 원본과 일치 |
| 실행 중 출처 보존 | D1/D2 1,204파일, 해당 원본 263파일, 실행 코드·설정·모델 | 종료 시 재확인 통과 |

R은 선형 동역학, S1은 한 단계 학습 MLP, SK는 한 단계와 0.1×5단계 자유 예측 손실로 학습한 MLP다. 숫자 접미사는 학습 seed다. 이번에는 모델을 학습하거나 최적화 상태를 갱신하지 않았다.

N-T tick78의 전체 내부 상태는 이전 D1에서 **새로 복원해 저장한 상태**다. 원래 실행에는 해당 tick의 내부 전체 snapshot이 없었으므로, 없던 원본 snapshot과 직접 비교했다고 주장하지 않는다. D1의 원시 전이·문맥·후보 일치 근거를 승계하고, 이번에는 그 복원 입력의 동일성과 실제 환경 복원을 검사했다.

## 3. 예측·실제 실행·기록 순서

1. 원본·입력·128후보·모델을 인증한다.
2. 동일 128후보에 대한 7모델의 H5 예측·비용·선택·유효성 배열을 저장하고 비트 단위로 재읽기 검사한다.
3. 기존 D2의 A 첫 반복 16후보에서 80개 전이를 재구성한다. 이를 정확히 8회 반복한 640행 입력으로 최대 크기의 평가 비용을 측정한다.
4. 예측과 평가 자료의 해시를 `prospective_forecast_seal.json`에 기록한 뒤에만 새 실제 미래를 실행한다.
5. 각 실제 반복의 원시 prefix를 fsync·해시와 함께 저장한 뒤, 왕복 비교·원본 대조·전체 실행 결과 반복 비교를 한다. 비교기에서 오류가 나도 이미 반환된 원시 자료를 먼저 남긴다.
6. 각 후보·패널 첫 반복은 전체 `FollowupProbe` 필드와 모든 `StepResult`를 저장하고, 원래 dataclass로 복원해 exact 비교한다. 마지막에 예측 봉인·원본·모델·코드·설정을 다시 인증한다.

640행은 **처리 시간 측정을 위한 반복 입력**이다. 새로운 독립 전이 640개, 추가 학습 자료 또는 일반화 평가로 사용하지 않는다. 전체 128 배치의 부동소수점 예측값을 이전 16배치와 비트 단위로 같아야 한다고 요구하지도 않는다. 고정 입력·가중치의 해시와 저장 배열의 정확성을 검증하며, 실제 물리·원시 자료의 exact 기준은 유지한다.

모델 전용 예측과 평가 중 미래 물리 엔진 호출은 5종 모두 **0회**였다. 실제 미래는 예측 저장 이후 별도 환경에서 실행했다.

## 4. 실제 사전 실행은 어디까지 통과했는가

| 검사 | 결과 |
|---|---|
| 예정 18건·반복 누락 | 18건 완료, 자동 재시도 없음 |
| 물리 기록 | 111구간·22,200 하위 표본, 모두 물리 유효 |
| 원시 저장·재읽기 | 18건 전체 초기 snapshot·모든 StepResult exact |
| 전체 실행 결과 반복 | 6개 후보·패널 조합에서 3회 전체 결과 exact |
| 첫 반복 완전 결과 저장·복원 | 6건의 전체 필드·중첩 타입·최종 snapshot exact |
| 기존 D2와 대조 | 원본이 있는 후보0·9의 12건 raw exact; 후보127에는 이전 D2 실제 기록 없음 |
| 독립 저장 자료 검산 | 18건 task/hold/status 재판정, A 9건의 9항 비용, 7모델의 저장 예측 비용·선택·기하 계산 일치 |

최대 117구간보다 6개 적은 것은 후보9의 B가 세 번 모두 6번째 구간(0.6초)에 ready로 종료했기 때문이다. 누락이 아니다. A는 0.5초 명령 고정, B는 현재 자세에 따른 정지 명령과 최대 0.8초 관찰을 포함한다. B에는 원래 H5 비용을 적용하지 않는다.

이 18건은 실행기 검사이며, 128후보 전체의 실제 결과가 아니다. 전체 예측이 저장됐다는 사실만으로 실제 비용 순위·인계 가능 후보·모델 우위가 확인된 것은 아니다. 특히 B의 0.6초 ready를 A의 0.5초 비용 정답으로 취급하지 않는다.

표의 부분 단계는 실행 전 전체 시간에 포함되며 중복해서 더하지 않는다. 전체 프로세스는 외부에서 측정해 인터프리터 시작과 최종 summary 저장까지 포함했다. 내부 기록 시간 69.641초보다 큰 외부 측정값을 예산에 사용했다.

고정 비용은 작은 편이지만 반복 검증과 첫 반복 완전 결과 저장은 후보 수에 따라 늘어난다. 이전 약 72분 추정에 새 첫 반복 저장·복원 비용을 추가하지 않고 그대로 진입하면 안 된다.

## 6. 누적 2시간 판단: 적용 대상별로 계산

먼저 원본 D2 대조까지 들어 있는 최대 구간 단가를 모든 후보에 적용하면 [보수적 일괄 계산 v1](../artifacts/followup/20261022-nt-preflight/resource_projection.json)은 **124.13분**으로 보류다. 이 계산은 보존했다.

다만 원본 D2의 실제 미래는 후보0–15에만 있다. 다음 전체 실행에서 그 16후보·A/B·3반복의 **96건을 모두 원본과 대조**하고, 나머지 112후보에는 새 raw 왕복·전체 결과 반복 검증을 수행하는 실제 적용 범위로 [별도 계산 v2](../artifacts/validation/nt_fullbank_resource_budget.v2.json)를 만들었다. 원본 대조를 없애거나 검증을 느슨하게 한 것이 아니다.

| 다음 실행 작업 | 적용 수 | 안전계수 적용 계획 시간 |
|---|---:|---:|
| 물리 실행·새 raw 저장/인증/왕복·전체 결과 반복 검증 등 | 최대 4,992구간 | 3,602.93초 |
| 원본 D2 raw 대조 | 원본이 있는 96건 모두 | 166.38초 |
| 첫 반복 완전 결과 저장·복원 exact | 128후보 × 2패널 = 256그룹 | 1,579.93초 |
| 실행 루프의 기록·부대 작업 | 768건 | 6.61초 |
| 모델·입력·예측·평가·최종 인증 고정 작업 | 640행 입력 인증까지 반영 | 12.12초 |
| 보고·전체 실행 진입 코드 준비 여유 | 미측정 계획 여유 | 120초 |
| **앞으로 필요한 시간 합계** | 기존 D2·사전 검사 실제 궤적 행 재사용 없음 | **91.47분** |

기준 구간 단가는 새로운 적용 범위 측정값과 과거 최대 0.481161초 중 큰 값을 사용한다. 과거 최대값과 안전계수 **1.5**를 유지했다. 전체 640행 입력을 다시 인증하는 비용은 80행 인증 실측의 8배로 잡고, 평가 벤치마크 비용도 유지했다.

- 이미 사용한 기록 실행 시간: **662.51초(11.04분)**. D1/D2·시간 측정·첫 실패·두 번째 사전 검사 모두 포함한다.
- 다음 전체 실행까지 누적 계획: **6,150.48초 = 102.51분**.
- 누적 2시간 상한 대비 계획 여유: **17.49분**.
- 전체 원시·첫 반복 완전 결과를 보존한 누적 저장량: **약 0.963GiB**. 추가 저장 계획은 약 0.876GiB이며, 5GiB 상한과 디스크 여유 2GiB 조건에 들어간다.

이는 속도를 개선한 실험 결과가 아니라 **작업별 적용 수를 구분한 자원 계획**이다. 아직 관측하지 않은 모든 후보의 시간을 보장하지 않으며, 전체 실행 직전에 현재 여유 공간과 누적 시간·작업 단가를 다시 확인해야 한다. 새 전체 진입 코드는 사전 검사의 같은 핵심 함수를 사용하고, 위 96건 원본 대조·256그룹 완전 결과 보존·실행 중 상한 검사를 유지해야 한다.

## 7. 첫 시도 실패와 정정

첫 시도 `followup-nt-preflight-20261022-01`은 실제 미래를 실행하기 전에 중단됐다. 실행기가 모델·정규화 파일을 24개라고 단정했으나, 원래 D2 entry의 실제 전체 목록은 **정규화2 + R2 + 6×MLP3 = 22개**였다. 초기 검토도 이 잘못된 개수를 놓쳤다.

실패 기록과 당시 실행기·검사·검토를 보존했다. [정정 기록](../artifacts/validation/nt_preflight_binding_correction.v1.json)에 이전 문서와 검토 기록의 잘못된 개수, 실제 22파일 경로→SHA, 수정 범위를 명시했다. 기존 사람용 D1/D2 보고서만 22개로 정정하고 이전 검토 JSON은 이력으로 남겼다.

새 v2는 파일 개수를 추정하지 않고 **원래 D2 목록 = 설정의 목록 = 새로 로드한 목록** 전체를 비교한다. 누락·추가·해시 변경을 거절하는 회귀 검사를 추가해 총 5개 검사가 통과했다. 실패에 쓴 2.572초와 81,769B도 누적 예산에 포함했다. 새 결과는 `followup-nt-preflight-20261022-02`에 저장했으며 이전 결과를 덮어쓰거나 모델을 바꾸지 않았다.
