# 목표 근처·실패 직전의 동일 후보 미래 대조: 보완 실험 설계 v1

2026-10-22 · **DESIGN_ONLY / 미실행** · 기존 동결 비교 이후의 개발 진단

## 1. 문제와 이번에 답할 질문

학습한 미래를 이용해 부품을 목표 위치·방향에서 멈추게 하려 했지만, 일부 고정 행동의 위치 예측 개선은 최종 인계 성공 개선으로 이어지지 않았다. 기존 E1의 실제 후보 끝점은 목표에서 최소 49.462125mm 떨어져 있었다. 따라서 E1만으로 마지막 5mm 정렬·정지·유지 실패를 설명할 수 없다.

이번에는 **동일한 목표 근처 상태에서 동일한 후보 명령열을 모델과 실제 물리에 각각 입력**한다. 모델의 잘못된 예측·거절, 실제 비용과 준비 조건의 불일치, 제한된 후보군의 부족을 구별한다. 실제 미래는 오프라인 분석에만 사용하고 온라인 계획에 제공하지 않는다.

원래 E1/E2, 성공 분모, 모델 가중치, 정규화, 물리·접촉, 9항 비용, 성공 기준을 유지한다. 새 진단의 성패로 과거 결과를 교체하지 않는다. 학습 기반 계획을 제거하거나 모델을 재학습하는 실험도 아니다. 이 설계는 원인 가설을 좁혀 **다음 모델·학습·계획 수정의 근거**를 만드는 단계다.

기계가 읽을 설정은 [설계 JSON](../configs/followup_candidate_diagnostic.v1.json), 저장 자료만 읽은 상태 선정 근거는 [선정 기록](../artifacts/validation/followup_state_selection.v1.json)이다. 새 전체 snapshot과 후보 재구성의 해시는 복원 검사 후 기록한다. 아직 없는 해시는 만들지 않는다.

## 3. 상태 선정: 여섯 snapshot, 다섯 초기조건

목표 근처 후보는 실패한 S1/SK 경로의 유효한 active 행동 경계 중 `시간 ≤29.2s, 위치오차 ≤15mm, 방향오차 ≤9°`로 제한한다. 각 층(병진·회전·오프셋)에서 `sqrt((위치오차/5mm)^2 + (방향오차/3°)^2)`가 가장 작은 상태를 고른다. 동률은 family ID·controller ID·tick 순서다. 제곱근을 취하기 전 제곱합으로 구현해도 순서는 같다. 속도를 기준으로 추가 선별하지 않는다. 15mm·9°는 성공 기준의 세 배인 **진단용 근방**이며 성공으로 인정하는 문턱이 아니다.

별도로, S1의 `planner_invalid` 3건은 실패 판정 직전의 미실행 입력을 모두 포함한다. 후보나 실패 유형을 보고 다른 사례로 대체하지 않는다.

실패 직전 세 상태는 저장 `input.json.gz`·`trace.npz`의 후보 배열 및 계획 identity와 직접 대조한다. 다른 세 상태는 원본 초기 전체 snapshot부터 **실제 적용 명령**으로 재생해 복원하고, 원본 witness·plan_index의 후보 해시와 맞춘다. 관측 상태10만 같다고 복원 통과로 인정하지 않는다.

실제 적용 명령은 목표 속도 명령이며 실제 푸셔 속도와 다를 수 있다. 예측·실제 모두 푸셔를 포함한 상태10을 비교한다. 모델은 접촉력·접촉 여부를 직접 예측하지 않으므로 예측 상태에서 계산한 접촉 간격·침투는 **기하 대리지표**로 표시하고 실제 MuJoCo 접촉·힘 기록과 구분한다.

## 5. 두 검사를 구별한다

### A. 같은 명령·같은 0.5초: 모델과 비용의 직접 대조

각 후보의 명령 5개를 모델에 연쇄 입력하고, 별도의 물리 복사본에도 동일하게 전부 적용한다. **미래 재계획·목표 자세 안 영 명령 전환은 적용하지 않는다.** 따라서 예측과 실제가 같은 명령·같은 길이를 갖는다. 기존 `candidate_replay`는 이 고정 명령 재생을 제공하지만 인계 판정은 제공하지 않으므로 수동 관찰용 판정을 별도로 추가해야 한다.

기록할 항목은 단계별 상태10 오차, 상대위치·방향·선속도·각속도 오차, 첫 무효 단계/사유, 비용 9항과 합계, 모델 선택 후보 ID, 실제 비용 최선 ID다. 같은 실제 경계 상태에서 다음 실제 0.1s를 맞추는 **한 단계 대조(teacher forcing)**도 기록한다. 학습·가중치 갱신은 하지 않는다. 첫 전이부터 어긋나는지, 실제 상태를 다시 넣으면 줄어드는지, 자유 예측에서 누적되는지를 구분할 자료다.

TaskStatus는 원래 시간·이미 유지한 시간에서 시작해 실제 0.5ms 표본으로 **수동 관찰**한다. 명령은 바꾸지 않는다. 최초 ready가 확인된 행동 경계(`first_ready_A`), H5 전체 물리 유효성(`H5_physical_valid`), 비용 비교에 쓸 준비 후보 여부(`ready_A_eligible`)를 분리한다. 이 문서의 ready_A는 전체 H5가 유효하며 최초 ready가 있었던 후보를 뜻한다. ready 이후에는 공식 최초 판정을 고정하고 비용 계산용 물리만 H5까지 이어간다. terminal TaskStatus에 `consume_step`을 재호출하지 않으며, 끝점 유지시간은 별도 비종단 진단용 hold tracker로 추적한다. 물리 무효가 발생하면 원래 replay 규칙대로 중단하고 prefix·사유를 보존한다. 물리 무효인 후보는 비용·준비 달성의 유효 후보로 쓰지 않는다.

이 검사는 원래 폐루프 제어기의 재실행이 아니다. 수동 관찰에서 ready가 안 나왔다고 정상 감독기가 있었어도 실패할 것이라 단정하지 않는다. 반대로 ready_A는 관찰 구간 안 준비 조건을 충족했다는 뜻이며 그 이후 영구 정지나 후속 집기 성공을 뜻하지 않는다.

### B. 같은 명목 후보 + 원래 정지 규칙 + 0.3초 영 명령

A와 같은 시작·명목 후보에서, 각 행동 경계의 **실제 자세**가 목표 안이면 기존 감독기처럼 영 명령으로 바꾼다. 한 번 진입한 뒤 영 명령에 고정하는 latch가 아니다. H5 안에서 자세가 다시 벗어나면 그 단계의 원래 명목 명령을 적용하고, k≥5에서만 무조건 영 명령을 쓴다. 5단계 이후에는 모든 후보에 동일한 3단계 영 명령을 붙인다. 최대 0.8s 안에서 원래 속도·연속 유지·30초 제한을 검사한다. 0.5초까지의 최초 ready(`ready_B_prefix`)와 최대 0.8초의 최초 ready(`ready_B`)를 모두 기록한다. ready/물리 실패/원래 제한시간에 종료한다. 원래 시각·유지 이력은 초기화하지 않는다.

A의 first_ready_A와 B의 ready_B_prefix는 같은 0.5초 안의 최초 준비 도달을 비교한다. 다만 A가 ready 후 계속 실행해 물리 무효가 되었고 B는 ready에서 종료했다면 `A_POST_READY_INVALID / B_ABSORBING_READY`로 표시한다. 이것은 감독기 명령 효과가 아닌 실행·종료 규약 차이다. 이 경우를 제외하고 실제 명령이 바뀐 prefix에서만 감독기 개입의 국소 효과를 논의한다. B_prefix에서 준비되지 않았으나 B에서 준비됐다면 추가 정지·관측시간의 효과를 나타낸다. 이는 같은 B 경로의 시점별 관찰이며 독립 실행 표본은 아니다. 0.3초 영 명령을 붙였다고 0.3초 준비 조건 유지가 보장되는 것도 아니다. 자격 조건 진입이 늦거나 다시 벗어날 수 있다.

이것은 **후보를 일단 선택해 따르는 정지 규칙 대조**이며 이후 모델 재계획까지 포함한 전체 MPC는 아니다. 실제 명령이 A와 달라질 수 있으므로 A의 예측 비용과 B의 실제 상태 오차를 “같은 미래의 예측 오류”로 계산하지 않는다. 명목·실제 명령, 영 명령 전환 위치, 최초 ready, 감속·유지 이력을 함께 저장한다. A 대비 B 전체의 차이는 개입과 관찰시간이 함께 변한 결과다. B의 0.5초 경계 비용을 저장한다면 A와 별도 열로 표시하며, 0.8초 비용을 원래 H5 비용처럼 계산하지 않는다.

A에서는 침투·무효이고 B에서는 준비가 된다면, 고정 rollout과 감독기 실행의 호환성 가설이 생긴다. 이를 모델의 **거짓 무효 예측**이라고 부르지 않는다. B에서만 비용 최선과 ready가 어긋나면 비용·평가 길이·감독기 인터페이스가 함께 얽힌 결과이며 비용만의 단독 원인으로 분류하지 않는다.

## 6. 어떤 결과로 가설을 구별할 것인가

각 실제 후보를 새 복사본에서 3회 실행한다. 이는 결정론·복원 일치 검사이며 독립 환경 잡음의 추정이나 신뢰구간이 아니다. 3회 모두 같은 물리 유효성·ready 판정을 보이는 후보만 아래의 안정된 판정에 사용한다. 다르면 `UNSTABLE_REPLAY`로 남기고 원인 결론을 보류한다.

세 반복 모두 실제 유효한 후보의 유한 비용만 사용해 반복 범위를 `[L_i,U_i]`로 두고, `ε=10^-6 + 10^-5×max|그 유한 비용|`를 쓴다. 유효 후보가 하나도 없으면 비용 순위·선택손실·ε는 null이며 `NO_VALID_ACTUAL`로 남긴다. 무효의 inf 비용을 ε 계산에 넣지 않는다. `L_i ≤ min_j U_j + ε`인 후보를 비용상 최선일 수 있는 집합으로 보존한다. 오차 범위가 겹치면 낮은 인덱스 하나를 정답으로 삼지 않는다.

| 가설 | 지지하는 관찰 | 이 관찰만으로 주장하지 않을 것 |
|---|---|---|
| M1: 모델/예측 유효성의 거짓 거절 | **A에서** 실제 3회 모두 유효한 후보를 특정 모델이 무효로 거절. 실제 비용·ready_A도 함께 기록 | 그 후보가 전체 폐루프에서 성공한다는 주장, 모든 모델 실패의 원인 |
| M2: 모델에 의한 잘못된 비용 순위 | 모델 선택 후보 i가 A에서 실제 무효이거나, 다른 유효 후보 j에 대해 `L_i > U_j+ε`. 실제 선택손실과 9항 차이를 기록 | 실제 비용 최선이 곧 인계 최선이라는 주장. 전 후보 예측 무효는 손실 0으로 처리하지 않음 |
| C: 기존 비용과 준비 목표의 불일치 | A에서 안정된 ready_A 후보가 있고, 비용 최선 가능 집합은 모두 non-ready이며, 비용 최선 non-ready의 상한이 모든 ready 후보 하한보다 ε 이상 낮음 | 그 불일치가 E2 실패의 유일한 원인이라는 주장. 최선 집합에 ready/non-ready가 섞이면 `C_TIE_OR_UNRESOLVED` |
| I: 비용·길이·정지 규칙 인터페이스 | A의 결과와 B의 결과가 명령 전환·영 명령 뒤에 달라짐. 특히 ready_B는 있는데 A 기준의 선택 후보는 B에서 실패 | B의 차이를 순수 모델 예측 오류 또는 순수 비용 결함으로 환원 |
| S: 유한 후보군의 부족 | 같은 검사 A 또는 B에서 기본 128개가 모두 완료되고 UNSTABLE/MISSING 없이 모두 안정된 non-ready 또는 안정된 invalid이며, 아래 사전 고정 추가 128개에는 안정된 ready가 존재 | 최적 탐색 알고리즘의 우위, 태스크 전역 도달 가능성·불가능성 |
| 보류 | 실제 후보도 모두 무효, ready 후보 없음, 수치 동률, 반복 불일치, 복원 실패, 자원상 미실행 | 근거 없이 M/C/S 중 하나를 강제로 선택 |

가설은 서로 배타적이지 않다. 같은 상태에서 거짓 거절·비용 불일치·후보 부족이 함께 나타날 수 있다. 모델 평균 오차가 작아도 행동 선택을 바꾸는 특정 무효·순위 오류를 따로 본다. 반대로 예측 오차가 커도 같은 유효 후보를 골랐다면 그 상태의 선택 차이까지 입증한 것은 아니다.

### 후보 부족의 조건부 대조

기본 후보 전체를 검사해 ready가 없고 불안정·누락도 없는 검사에 한해, 같은 H5·[2,3]·속력·예약 후보 구조를 유지한 **추가 128개**를 딱 한 번 사용한다. 추가 난수 stream ID는 1로 미리 고정한다(원래 stream 0). 기존 후보를 교체하지 않고 256개 합집합으로 보며 중복 후보도 ID·일치 관계를 남긴다. 성공이 나올 때까지 재추첨하지 않는다. 모델 비교에는 추가 후보도 일곱 모델 모두 사용한다.

A는 A끼리, B는 B끼리 비교한다. A의 S는 전체 H5 물리 유효성과 관찰된 준비를 함께 만족하는 후보의 커버리지에 한정되며, ready 이후 무효가 된 행동까지 정상 종료 태스크에서 준비 불가능하다는 뜻은 아니다. 불안정·누락이 있다면 S는 `UNRESOLVED`다. 이 경우 확장을 임의 진행하지 않고 먼저 기록·재생 문제를 검토한다. 두 집합 모두 ready가 없으면 짧은 H5, 두 구간 행동 표현, 정지 규칙, 실제 복구 불가능성 등은 **미분리**다. 이번에 H10·새 행동 표현·새 비용으로 동시에 바꾸지 않는다. 필요하다면 그다음 설계에서 한 요인씩 바꾼다.

## 7. 단계별 진입·완료·중단 기준

| 단계 | 실행/산출물 | 완료 기준과 다음 판단 |
|---|---|---|
| D0 설계 등록 | 이 문서·JSON·6상태 선정 근거 | 기존 자료만 읽어 상태와 규칙 고정. 이번 요청의 범위 |
| D1 복원 검사 | **F-O0: offset-00/S1-23 tick254 하나**의 전체 snapshot·원래 입력·후보 identity | 원래 전체 상태/문맥·시간/직전 명령·후보 해시 일치. 불일치 시 새 미래 실행 전에 중단, 추적 근거 기록 |
| D2 작은 사전 실행 | N-T와 F-O0의 원래 후보 인덱스 0–15, 3반복, A/B | 모델 상위 후보만 고르지 않음. 반복·명령·물리·준비 판정·raw/요약 저장 왕복 검사 및 실측 자원 산정 통과. ready가 없어도 검사 자체는 통과 가능 |
| D3 본 진단 | 6상태×128후보×3반복×A/B, 7모델 예측 | 누락/무효/실패 보존, 모든 행의 상태·후보·모델·반복·해시 연결. 상태별 M/C/I 또는 보류 판정 |
| D4 조건부 탐색 | 필요한 상태/검사에 stream1 추가 128개 | 실행 전에 자원 재확인, S 또는 보류. 기본 후보 결과 덮어쓰기 없음 |
| D5 해석·수정 제안 | 사례표·대표 궤적·각 가설의 지지/반증/미분리 표 | 무엇이 확인됐고 다음에 무엇 하나를 바꿀지 정함. 재학습/비용 변경/정식 E2 재실행은 별도 설계 |

복원은 원본 초기 snapshot과 기록된 명령 prefix를 사용한다. 압축 raw의 상태10·시간·명령 및 witness 문맥을 원본 정밀도로 대조하고, 저장된 전체 입력이 있는 F-O0 등에서는 전체 integration state까지 비교한다. 임의 tick의 원본 전체 snapshot이 없으면 재생한 전체 snapshot을 저장하되 **원본에 없던 모든 내부 상태까지 직접 대조했다는 표현은 쓰지 않는다.** 후보 해시 및 가능한 기록 범위가 일치해야 통과하며, 복원 방식·대조 범위·허용오차를 실행 전 manifest에 명시한다. 원래 deterministic replay의 exact 경로를 우선 사용하고 임의의 느슨한 오차로 통과시키지 않는다.

인프라 오류·복원 불일치·기록 누락은 `INCOMPLETE`다. 완료한 prefix를 보존하며 자동 재시도·결과 교체는 하지 않는다. 보완 후에는 새 run/version으로 시작한다. 과학적 실패는 정상 결과로 남기고 인프라 실패와 분리한다.

## 8. 자원 상한과 남길 증거

기본 A는 `6×128×3×5=11,520` 행동 구간, B는 최대 `6×128×3×8=18,432` 구간이다. 합계 최대 **29,952구간 / 물리 5,990,400 substep / 시뮬레이션 2,995.2초**다. 조건부 확장을 전부 수행하면 최대 두 배다. 이는 물리 시뮬레이션 분량이며 벽시계 소요시간 예측이 아니다. 여기에 5개 원 경로를 각 최대 필요 tick까지 한 번 재생하는 복원 1,017구간(78+183+254+259+243)과, D2를 별도 실행으로 보존할 경우 최대 1,248구간이 추가된다. D1에서 offset-00 tick246·254 snapshot을 함께 저장해 뒤에서 재사용하며 중복 prefix 재생을 기본 계획에 넣지 않는다. D2는 드라이버·코드·설계·입력·후보 해시가 D3와 모두 같고 기록 검사를 통과한 경우에만 동일 행으로 재사용한다. 수정이 필요하면 D2 원본을 보존하고 새 버전의 실행 예산을 다시 산정한다. 확장과 별도 D2까지 포함한 계획상 상한은 62,169구간이며, 재생 검사 등 부대 작업도 아래 자원 총상한에 포함한다. 일곱 모델의 기본 자유 예측은 `6×128×5×7=26,880` 전이 행이다. teacher-forced 한 단계 추론은 실제 A 경계가 모두 유효하면 최대 26,880행이 추가된다(실제 반복이 동일할 때 첫 반복의 경계만 사용). 같은 실제 미래를 모델마다 반복 실행하지 않는다.

설계상 새 저장량 상한은 **5GiB**, 사용 후 남길 여유는 **2GiB**, 벽시계 상한은 **2시간**으로 둔다. 이 값은 검증된 성능치가 아니라 실행 한도다. 사전 검사의 구간당 최대 저장량·실측 시간을 1.5배로 잡아 D3/D4 전에 각각 재산정한다. 초과하면 실행 전에 멈추고 `NOT_RUN_RESOURCE`로 남긴다. 모델·반복 수·핵심 검사를 조용히 줄이지 않는다. 상한 변경은 새 설계 버전으로 기록한다. M1/M4 CPU/MPS의 실제 실행 환경·정밀도·버전도 manifest에 남긴다.

원본 raw를 복제하지 않고 참조 SHA로 연결한다. 새 run에는 다음을 보존한다.

- `design/config/source_hashes`: 동결 manifest, 코드, 가중치·normalizer, 선정 입력 및 새 설계 해시.
- `snapshots`: 새 전체 시작 snapshot과 원래 TaskStatus·계획/G 문맥, 복원 대조 보고서. 아직 복원하지 않은 값은 pending.
- `banks`: 명목 명령 `[128,5,2]`, 예약 후보 유형, RNG key, 후보 해시, 확장 시 원래 ID·중복 관계.
- `predictions`: 7모델의 `[128,6,10]` 상태(시작 포함), 단계별 유효/사유, 9항 비용, 선택 ID, teacher-forced 대조. 무효 prefix와 비유한 마스크도 보존.
- `actual/A,B`: 반복별 실제 명령·경계 상태·시간, 매 0.5ms의 판정용 상태10, 접촉·물리 유효/사유, ready 최초 경계·유지 이력·중단. 실제 측정 접촉과 예측 기하 지표 분리.
- `summary`: 후보별 비용 범위·유효/준비 결과, M/C/I/S 또는 보류 근거, 누락 목록·자원·재생 검사. 전체 integration state를 매 substep 저장하지 않는다면 그 생략도 명시.

그림은 같은 상태·후보에 예측/실제 XY·yaw·속도·간격을 시간축으로 겹치고, A/B 명령 차이는 별도 패널로 보여준다. 상위 성공 사례만 고르지 않고 모델 선택, 실제 비용 최선, ready 후보(존재 시), 거짓 무효 후보(존재 시)를 고정 규칙으로 표시한다. 동률은 가장 작은 원래 ID다. 각 그림에서 R·S1·SK와 단위·초기조건·tick·검사 A/B를 다시 정의한다.

## 9. 이 진단으로 남길 역량과 주장 범위

핵심 작업은 학습 동역학의 **입력 상태·행동·시간 계약을 복원하고**, 자유 예측·한 단계 재입력의 차이를 분석하며, 모델 오류가 유효성·비용 순위·행동 결과에 미치는 영향을 구분하는 것이다. 코드를 모두 직접 타이핑했는지보다 이 비교의 통제·수정·해석을 책임지고 설명할 수 있는지가 중요하다.

새 결과가 나오면 “이 여섯 저장 상태와 후보 표현에서 어떤 모델이 어떤 후보를 잘못 거절/선택했는가”, “비용과 준비 목표가 어디서 달랐는가”, “한 번의 후보 확장이 빠진 행동을 찾았는가”까지 주장할 수 있다. 일반 로봇 작업·새 형상·현업 빈도·실물 인계·단독 실패 원인·학습 방법 전반의 우위는 주장하지 않는다.

**가장 먼저 할 행동은 F-O0의 복원·후보 identity 검사 하나다.** 통과한 다음에만 미래 물리 대조용 구현과 작은 사전 실행으로 넘어간다. 현재는 D0만 문서화했고 D1–D5는 미실행이다.
