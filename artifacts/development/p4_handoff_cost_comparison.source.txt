## 1. 평가의 목적은 맞췄지만 실제 인계 개선은 확인하지 못했다

학습 모델이 미래 움직임을 예측하고 후보 행동을 고르는 구조를 유지하면서, 위치·방향·속도의 허용 조건과 유지 시간을 평가에 반영했다. 기존 비용은 문턱 안의 방향 오차를 더 줄이는 이득으로 위치 문턱 밖의 정지를 선호할 수 있었다. 새 평가는 네 인계 조건의 동시 충족과 예측 끝점의 유지 사건을 우선한다.

실제 기록으로 평가하면 새 규칙은 인계한 후보11을 인계하지 못한60보다 우선했다. 그러나 학습 예측에 적용하면 세 모델 모두77을 선택했다. **77은 예측상 0.7초에 유지 조건을 충족했지만, 실제 1초 실행에서는 인계하지 못했다.** 같은 상태에서 최대2초 동안 다시 계획한 비교도 모든9셀에서 인계하지 못했다. 평가의 목적 정합성과 실제 행동 개선을 구분한다.

## 2. 바꾼 부분과 유지한 부분

비교의 입력은 [기존 Common11 실패 경로](../runs/p3-05-20261010-01/full_resource/MLP-11/summary.json)의 tick99다. 해당 시점의 전체 물리 상태, 원래 태스크 경과9.9초, 이전 적용 행동·warm sequence·G 문맥을 복원했다. 현재 상태의10값과 행동2값을 기존11특징으로 변환하고, 고정된 모델의10차원 상태 증분을 적분하는 역할은 그대로다. 모델·정규화·자료·학습 손실·가중치는 변경하지 않았다.

| 계약 | 이번 구현 |
|---|---|
| 행동 후보 | 원래N128·H5·2/3블록, 세계 좌표 XY 속도 `[128,5,2]` |
| 정지 평가 | 모든 후보 뒤에0명령5개를 동일하게 붙인 `[128,10,2]`. 학습 모델만10단계 재귀 예측 |

| 실행 | 첫0.1초만 실행한 뒤 실제 상태에서 재계획. 예측한 정지 suffix를 끝까지 실행한다고 보장하지 않음 |

[사전 등록v1](../configs/p4_handoff_cost.v1.json)에 설계·가설·660구간 상한을 고정했다. 기록 비교 오류 뒤에는 [v2](../configs/p4_handoff_cost.v2.json)로 이미 수행한500구간의 재사용과 남은160구간만 등록했다. 기존 성공 기준·비용 가중치·모델을 결과에 맞춰 재조정하지 않았다.

## 3. 비용 효과와 정지 평가 효과를 분리한 설계

| 평가 방식 | 사용하는 예측 | 결정 방식 | 확인할 차이 |
|---|---|---|---|
| J_H5 | 원래 앞5단계 | 기존 가중 합 비용의 최소값 | 원래 계획의 참조 |
| J_H10_stop | 앞5명령+정지5명령의 같은10단계 | 기존 비용의 최소값 | 정지 구간까지 보는 효과 |
| TASK_H10_stop | J_H10_stop과 정확히 같은10단계 | 인계 중심 사전 순위 | 비용 평가만 바꾼 효과 |

비용만 바꾼 비교는 뒤의 두 방식이다. H5 대H10은 지평과 예측 무효 분모도 달라질 수 있다. 뒤5단계에서만 무효가 된 후보를 H5 참조에서 부당 제외하지 않도록 앞5단계의 유효성을 별도로 보존했다. 이번 최초 예측은 세 모델 모두 H5·H10·새 순위의 적격128/128이었다.

각 예측 상태에서 위치·방향·선속도·각속도를 각각 실제 허용값으로 나눈다. `e_t = max(네 정규화 비율 - 1, 0)`의 최댓값을 사용하므로, 이미 허용 범위 안인 방향 오차를 더 줄여 위치 조건 위반을 상쇄할 수 없다.

새 순위는 **① 예측 유지 미충족 여부 → ② 최초 예측 ready 경계의 최대 조건 초과량 → ③ 시간 누적 초과량 → ④ 기존H10 비용 → ⑤ 원본 후보 번호** 순으로 작게 고른다. ready가 없으면②는10단계 끝에서 계산한다. ③도 최초 예측 ready 시점까지만 누적하고, ready가 없으면10단계 끝까지 누적한다. 기존 비용은 전체H10의 최종 비교 기준으로 남겨 행동 크기·변화·접촉 간격 등의 부담을 보존한다. 인계를 우선한다는 설계자의 선택이며 유일하게 올바른 목적 함수라는 주장이 아니다.

유지는 **인접한 두 예측 끝점이 모두 네 조건을 만족할 때만0.1초를 누적**하고 조건이 끊기면0으로 되돌린다. 알려진 실제 초기 유지 이력만 이어받는다. 이번source99처럼 초기 끝점이 자격 밖이었다가 새로 진입하면 자격 끝점3개는0.2초만 덮으며,0.3초에는 최소4개가 필요하다. 초기 끝점부터 자격이 있으면 미래 끝점3개로0.3초를 덮는다. 끝점 사이 움직임은 모델이 관측하지 않으므로 이것은 연속 유지의 대리지표다. 실제 인계는 기존 원시 표본 감독기로 별도 판정한다.

## 4. 같은 후보에서 예측과 실제 결과가 갈라졌다

모든 최초 선택을 실제 미래 실행 전에 [동결](../runs/p4-cost-20261013-02/choices_before_new_physics.json)했다. 평가할16후보는 예약0~3,9선택의 합집합, 기존11/60을 포함한 뒤 낮은 번호로 채웠다. 실제 선정 목록은0~13·60·77이다. 중복 행동열을 제거하거나 무효 후보를 다른 후보로 교체하지 않았다. 후보 번호16개의 실제 고정 행동열은10종류이며 독립16상황이 아니다.

|---|---|---|---|---|
| Common11 | 60 | 60 | 77 | 예측0.7초 / 실제1초 안에 미충족 |

16후보×3회·H10의48재생/480구간은 모두 유효했다. 원시 인계는11의3반복에서만9번째 경계에 확인됐고, 다른15후보는1초 안에 확인되지 않았다. 11의0.9초는 source99 이후 시간이며 원래 작업 경과는10.8초다. 실제 비용은11의9.586888이60의8.804576보다 높지만, 새 실제 순위는11을 우선한다. 실제 미래를 넣어 고른 이 참조 순위는 온라인 제어에 사용하지 않았다.

학습 예측은 실제 성공한11의 마지막 위치를 Common/S1/SK에서5.594/5.390/5.255mm로 예상해 유지 후보에서 제외했다. 반대로 실제 위치5.542mm에 남은77은4.840/4.772/4.777mm로 예상했다. 평가한16후보에서 각 모델의 예측 긍정은77 하나이며, 실제 긍정은11 하나다. 각 모델의 TP0·FP1·FN1·TN14를 유지한다. N128 전체의 예측 긍정3/7/7개 중 평가하지 않은 후보의 실제 성공 여부는 모른다.

| 선택77의 예측 대 실제 XY 벡터 오차 | Common11 | S1-11 | SK-11 |
|---|---|---|---|
| 첫0.1초 | 0.364971mm | 0.414164mm | 0.410460mm |

이 값은 두 목표 거리의 차이가 아니라 예측·실제 XY 위치 차이의 노름이다. 첫 단계부터 오차가 있으므로 나중 단계의 재귀 누적만으로는 설명할 수 없다. 실제77은 위치 조건 밖이므로, 이번 잘못된 긍정을 끝점 사이의 유지 측정 해상도만의 문제로 설명할 수도 없다. 국소 예측·정지 예측·지원 자료·접촉 조건의 기여는 아직 분리하지 않았다. [분모와 오차 계산](p4_cost_prediction_diagnostics.json)을 남겼다.

## 5. 2초 재계획에서도 인계 개선은 없었다

동일source99의 태스크·G·warm 이력에서 세 모델×세평가를 최대20구간 실행했다. 처음 후보와 최초 선택은 위 동결 결과와 같았다. 이후에는 실제 상태·warm·G 문맥이 정책 결과로 달라지므로 모든 다음 후보가 같았다고 주장하지 않는다. 모델은 계속 미래를 예측했고, 실제 실행은 첫0.1초만 따랐다.

실제180구간은 모두 유효했고 유지 시간은0이었다. 원래 태스크 경과는11.9초이며, 아직30초 제한에 도달하지 않았다. **2초 내 인계 없음은 새30초 timeout과 다르다.** 선택이 바뀌어도 부품은 인계 위치에 들어오지 않았으므로 이 범위의 행동 개선은 NOT_DEMONSTRATED다. 처음부터의 전체 정책·다른 초기 조건·seed 전체에 대한 결론은 아니다.

## 6. 중단 기록과 완료 기록을 함께 보존했다

01은 당시889회귀를 통과하고480후보 구간과 첫20구간을 기록한 뒤, 태스크 상태의 `violations=()`와 JSON의 `violations=[]`를 직접 비교해 잘못 중단했다. 실제 마지막 태스크와 원시 기록을 다시 판정한 결과는 일치했다. 표현을 정규화하는 비교와 실제 상태 차이를 거부하는 회귀 검사를 추가했다.

02는 초기9선택·예측 hash·후보 배열이01과 같음을 물리 실행 전에 확인했다. 48재생은 파일 그대로 복사하고, 완료된 첫20구간은 원시 상태·행동·시각·태스크 이력을 검사해 요약을 복원했다. 나머지8셀/160구간만 새로 실행했다. **서로 다른 실행 구간은 합계660 = 재사용500 + 새160**이다. 파일 복사는 물리 표본이나 반복 횟수를 늘리지 않는다. 회복한 셀의 추론 호출 수는 중단 전에 저장되지 않아 추정 숫자를 만들지 않았다. 그 셀의 미래 접근 경계는20개 계획이 금지 호출 예외 없이 완료된 근거와 새8셀의 저장 계수를 구분한다.

[01 중단](../runs/p4-cost-20261013-01/failure.json)과 [재사용 증거](../runs/p4-cost-20261013-02/reuse_proof_before_physics.json)를 보존한다. 비용·모델·태스크 조건은 오류 수정 과정에서 변경하지 않았다.

## 8. 다음에 확인할 질문

독립 검산은 초기3개와 재계획180개의183 예측 묶음, 기존9성분 비용과 새 순위, 실제 시각·유지·행동·전체 스냅샷·237개 재사용 파일을 확인했다. 1,862,829개 수치 대조의 최대 수식 차이는1.23e-13이었고, 선택·원시 배열·해시는 exact였다. 검사 수는 독립 태스크 표본이나 성능 신뢰도를 뜻하지 않는다.

이번에 좁힌 질문은 **“실제로 멈춰 있는77을 움직여 목표 안에 들어간다고 예측하고, 실제로 인계하는11은 목표 밖이라고 예측하는 이유가 무엇인가?”**다. 현재 비용은 참조로 보존하고, 새 평가의 설계도 아직 정식 설정으로 채택하지 않는다. 비용을 더 튜닝하기 전에 같은11/77의 국소 전이·정지 suffix·다단계 오차와 학습 자료의 접촉 조건을 비교해 모델링 가설을 구별하는 것이 타당하다.

태스크의 의미, 예측한 유지, 실제 행동, 인계 성공이 다른 판정이라는 연결을 구현했다. 코드·실행·검산은 Codex가 수행했고 사용자는 학습 기반 계획을 유지한 비용 비교를 선택했다. 이를 사용자가 직접 모델 핵심을 설명·수정·검증할 수 있음을 확인한 것으로 환산하지 않는다. 이 단일 개발 상태의 결과를 실물 정확도·현장 비용 절감·연구 독창성·일반화로 확대하지 않는다.

현재 결과는 저장된 원시 기록과 [독립 검산](p4_cost_independent_review.json)으로 새 물리 실행 없이 확인할 수 있다. 새로 물리를 반복하려면 원본01·02를 보존하고 **현재 누적 저장량과 추가160구간 예산을 새 등록에서 먼저 확정**해야 한다. v2의 자원 수치는02 실행 전 값이므로 그대로 새 실행의 예산으로 쓰지 않는다. 아래는 새 등록 뒤의 호출 형식이다.

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:scripts .venv/bin/python scripts/p4_handoff_cost_compare.py --run-id NEW_RUN_ID --registry NEW_REGISTERED_CONFIG --registry-sha256 NEW_CONFIG_SHA256
```

같은 재사용 구성을 택하면01의500구간을 재검산하고 새160구간을 추가한다. 그 추가 실행을 이번에 이미 완료한660구간에 포함시키지 않는다.
